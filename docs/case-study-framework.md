# Case-Study Framework

## Definition

A case is a bounded professional-learning unit that connects one real shutdown context to a sanitized domain question and, later, to a reproducible synthetic analytical model.

A case is **not** a diary, a reconstruction of a real event, an employer record, or evidence that the proposed system was deployed.

The inspectable chain is:

**public context → limited personal claim → sanitized question → synthetic model → reproducible analysis → limitation → transferable finding**

## Evidence classes

Every material case statement must be attributable to one class.

| Class | Allowed content | Required control |
|---|---|---|
| `PUBLIC_CONTEXT` | Site or asset identity and other independently public facts | Cite source and record what it supports |
| `PERSONAL_EXPERIENCE` | Truthful, high-level facts about Martin's participation | Avoid confidential detail and unsupported inference |
| `SYNTHETIC_DATA` | Invented actors, events, timestamps, states, blockers, and outcomes | Mark mechanically and visibly as synthetic |
| `DERIVED_ANALYSIS` | Metrics or findings produced from declared inputs | Provide reproducible method and lineage |
| `UNKNOWN` | Anything not sufficiently evidenced | Do not fill, infer, or embellish |

One statement may not silently move between classes. Public information does not convert a private operational fact into publishable information.

## Case maturity states

| State | Minimum evidence |
|---|---|
| `REGISTERED` | Case ID, public context, personal scope, boundary, and source register |
| `FRAMED` | Sanitized problem statement, questions, hypotheses, and acceptance criteria |
| `MODELLED` | Versioned schema plus clearly synthetic scenarios |
| `TESTED` | Reproducible validations, results, limitations, and rejected assumptions |
| `SYNTHESIZED` | Cross-case comparison and a defensible professional narrative |

Maturity describes repository evidence, not operational competence or site approval.

## Mandatory case sections

Each case README must contain:

1. identity and maturity;
2. public context and source register;
3. limited personal-experience statement;
4. purpose and sanitized analytical question;
5. publication and authority boundary;
6. candidate learning themes;
7. planned evidence artifacts;
8. findings, limitations, and change log.

A blank or unknown field must remain explicit. It must not be completed from assumption.

## Naming policy

A real site or asset name may be used only when:

1. the identifier is independently visible in a public source;
2. the source is recorded in the case;
3. the name provides professional context rather than operational disclosure;
4. no accompanying combination of details exposes confidential activity;
5. publication remains compatible with employment agreements and applicable site policies.

Asset-level identifiers receive stricter review than site names. If any condition is uncertain, use a generalized label pending review.

## Separation rule

Real context and synthetic operations must never be visually ambiguous.

- Case identity may be real and publicly sourced.
- Martin's participation claim may be real but limited.
- Operational rows, timestamps, work-front states, blockers, ownership, evidence gaps, and outcomes are synthetic unless a future authorized source is explicitly documented.
- Synthetic records must use fictional identifiers and carry a machine-readable synthetic flag.
- Analysis must declare whether it operates on public, synthetic, or mixed inputs.

## Longitudinal cases

A case may be registered while field work is under way, but no live operational content is published. Development follows this sequence:

1. register only the permitted context;
2. observe privately within site rules;
3. delay publication;
4. extract generalized patterns after the work period;
5. create fictional scenarios;
6. test the model;
7. publish only the sanitized artifact.

## Professional value test

A completed case should allow a reviewer to verify, within five minutes:

- what real experience motivated the work;
- which claims are factual, public, synthetic, derived, or unknown;
- what operational-information problem was modelled;
- how the analysis can be reproduced;
- what the result demonstrates;
- what it does not demonstrate;
- how the finding transfers to another shutdown without claiming universal validity.

## Power BI boundary

Power BI is reserved for the later synthesis of a sufficiently mature multi-case evidence base. It will consume curated, validated, synthetic outputs. It is not the source of truth and does not precede the contracts, tests, or analytical definitions.
