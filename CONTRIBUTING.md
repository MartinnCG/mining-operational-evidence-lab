# Contributing

## Contribution standard

Every change should improve one of:

- domain clarity;
- evidence integrity;
- reproducibility;
- interoperability;
- governed decision support;
- explicit limitations.

Commit volume is not a goal.

## Required workflow

1. Start from an issue with a question and acceptance criteria.
2. Work on a focused branch.
3. Use synthetic or openly sourced inputs only.
4. Add tests or inspectable evidence where applicable.
5. Open a PR that explains why the change exists.
6. Declare confidentiality, claims, and portfolio impact.
7. Merge only after review.

## Commit style

Use concise conventional prefixes:

- `docs:`
- `feat:`
- `test:`
- `fix:`
- `refactor:`
- `chore:`

## Evidence requirements

A PR must identify:

- the question being answered;
- the artifact that provides evidence;
- how the result is reproduced or inspected;
- limitations and unsupported claims;
- whether another repository must be synchronized.

## Prohibited contributions

See [Confidentiality and Claims Boundary](docs/confidentiality-and-claims-boundary.md). If sanitization is uncertain, do not open the PR.
